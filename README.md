# 利根沼田 下校時刻共有システム（試作品）

学校が入力・公開した下校時刻を、**学童**と**保護者**がすぐに受け取れるようにする仕組みです。
沼田市・みなかみ町・川場村・片品村・昭和村（利根沼田地域）で共通して使うことを想定しています。

```
学校 ──入力──▶ 下書き ──公開──▶ 学童（画面・スマホ通知＋確認ボタン）
                         └──────▶ 保護者（閲覧ページ＋スマホ通知）
修正があれば直して再公開 → 「修正」として変更箇所だけが届く
```

### 通知について
- 学童・保護者はボタン 1 つで「通知を受け取る」設定ができ、**画面を閉じていても**パソコン・スマホに通知が届きます（Web プッシュ通知）。LINE などの外部サービスとの契約は不要です。
- 保護者の登録は匿名です（名前・メールアドレス・電話番号は不要）。
- iPhone・iPad は、Safari の共有ボタンから「ホーム画面に追加」したアイコンから開くと通知を受け取れます（iOS 16.4 以降）。

## 動かし方

Node.js（18 以上）だけで動きます。追加のインストールはいりません。

```sh
npm start          # http://localhost:3000 で起動
npm test           # 自動テスト
```

初回起動時にデモ用データ（架空の学校 8 校・学童 3 か所）が作られます。パスワードはすべて `demo1234` です。

| ログインID | 役割 |
|---|---|
| `council` | 連絡協議会 事務局（全体の管理・全体設定・バックアップ） |
| `numata-boe` など | 市町村の教育委員会（自分の市町村の学校を管理） |
| `numata-kodomo` | 沼田市 学童担当課（自分の市町村の学童を管理） |
| `school1`〜`school8` | 学校の管理職（下校時刻の入力・公開＋自校の職員アカウント管理） |
| `school1-staff` | 学校の職員（下校時刻の入力・公開のみ） |
| `gakudo1`〜`gakudo3` | 学童 |

協議会・教育委員会のアカウントは、最初のログイン時に2段階認証（スマホアプリの6桁コード）の設定が必要です。

## 管理体制

特定の民間事業者（塾など）はシステム内の管理権を持ちません。

```
連絡協議会（全体の管理。事務局は幹事市町村の教育委員会を想定）
  └ 市町村の管理者（教育委員会・学童担当課）… 自分の市町村の学校・学童だけを管理
      └ 学校・学童の管理職 … 自組織の職員アカウントを管理（人事異動への対応）
```

- ログイン・公開・承認・アカウント操作などはすべて操作履歴に残ります（協議会は全体、市町村は自分の市町村、管理職は自組織の分を閲覧）
- 異動・退職した職員のアカウントは削除ではなく「停止」にします（履歴に名前を残すため）
- 協議会・市町村の管理者は、30分操作がないと自動でログアウトします

保護者向けページはログイン不要です。学校の画面の「保護者向けリンク」からリンクを取得できます。

## 学校側が心配しそうな点と、その対策

| # | 学校の心配 | このシステムでの対策 |
|---|---|---|
| 1 | **先生の仕事が増えるのでは** | ・「曜日ごとにまとめて入力」で 1 か月分が数秒で埋まる<br>・今ある Excel の下校時刻表をそのまま貼り付けできる（全角数字・「10/3」「3」などの日付にも対応）<br>・時刻は `1445` と数字だけ打てば `14:45` になる<br>・印刷ボタンで今までどおり紙でも配れる（学童と保護者への個別連絡が不要になり、全体では手間が減る） |
| 2 | **間違えて公開したら困る** | ・入力は自動で「下書き」になり、公開ボタンを押すまで誰にも見えない<br>・公開前に「どの日の何年が何時から何時に変わるか」を一覧で確認できる<br>・11:00 より前や 17:00 より後の時刻、過去の日付は「入力ミスでは？」と警告する<br>・時刻として読めない入力は保存しない<br>・下書きの破棄や、1 日ずつ「元に戻す」ができる<br>・間違えても、直して再公開すれば学童には「修正」として届く |
| 3 | **知らない団体に情報が渡るのでは** | ・アカウントは市町村（教育委員会等）と各校の管理職だけが発行する（誰でも登録できるわけではない）<br>・学童は学校に「受信申請」をし、**学校が承認した学童にだけ**情報が届く<br>・学校はいつでも配信を停止できる |
| 4 | **防犯上、下校時刻が広く知られるのは不安** | ・児童の氏名などの個人情報は一切扱わない（学年ごとの時刻と備考だけ）<br>・保護者向けページは推測できない長いコード付きのリンクでしか見られない<br>・検索エンジンに載らない設定（`noindex`）<br>・リンクが広まった疑いがあれば、作り直すだけで古いリンクは即座に無効になる。ページ自体の停止も可能 |
| 5 | **本当に伝わったか分からない** | ・学童が「確認しました」を押すと、学校の画面に学童ごとの確認時刻が表示される<br>・未確認の学童が一目で分かる |
| 6 | **当日の急な変更（早帰り・悪天候など）が心配** | ・公開済みの当日・翌日分を変更すると「緊急」扱いになり、学童の画面に赤い通知とパソコン・スマホの通知が出る<br>・未確認の学童の電話番号が学校側に表示され、すぐ電話で確認できる |
| 7 | **誰が公開したのか分からなくなる** | ・先生ごとにアカウントを分けられ、公開履歴に「いつ・誰が・何を変えたか」が残る |
| 8 | **不正ログインが心配** | ・パスワードは暗号化（ハッシュ化）して保存し、平文では持たない<br>・同じ接続元から 5 回続けて失敗すると 10 分間ロック（他人がわざと失敗しても、先生は別の場所からログインできる）<br>・パスワード変更・管理者による再発行が可能（再発行するとログイン中の端末も自動でログアウト）<br>・2段階認証（協議会・教育委員会は必須、学校・学童も設定可能。必須にする範囲は協議会が決める） |
| 9 | **特別な機械やアプリが必要では** | ・パソコン・スマホのブラウザだけで使える。インストール不要（ホーム画面に追加してアプリのようにも使える） |
| 10 | **保護者からの問い合わせ電話が増えるのでは** | ・保護者のスマホにも直接通知が届き、ページ上部に「最近の変更」が出るので、見落としによる問い合わせを減らせる |
| 11 | **データが消えたら困る** | ・協議会の画面からいつでも全データのバックアップを保存できる |
| 12 | **規約や個人情報の扱いが決まっていない** | ・利用規約・プライバシーポリシーのたたき台を用意（`/terms.html`） |

## サーバーに置くとき

Docker で動かせます。スマホへの通知は **https の環境でしか動かない**ので、必ず https で公開してください。

```sh
docker build -t dismissal .
docker run -d -p 3000:3000 -v dismissal-data:/app/data \
  -e SECURE_COOKIE=1 -e TRUST_PROXY=1 -e PUSH_SUBJECT=mailto:（事務局のメールアドレス） dismissal
```

| 環境変数 | 意味 |
|---|---|
| `PORT` | 待ち受けるポート（既定 3000） |
| `DATA_FILE` | データの保存先（既定 `data/db.json`） |
| `SECURE_COOKIE=1` | https で公開するときに設定（ログイン情報を https でのみ送る） |
| `TRUST_PROXY=1` | ロードバランサー等の後ろに置くときに設定（接続元の判定に使う） |
| `PUSH_SUBJECT` | 通知の送り主の連絡先（`mailto:〜`）。通知サービス側の問い合わせ先になる |

**本番公開の前に**、デモ用アカウント（パスワード `demo1234`）を削除するか、データファイルを消して作り直してください。

## 本番運用に向けて残っていること

試作品としての機能は揃っています。実際に学校で使うには、次の準備が必要です。

- **教育委員会との協議**：各市町村の教育委員会に説明し、了承を得る（上の表と実際の画面を見せるのが近道）
- **サーバーの用意**：国内のクラウドに置き、https で公開する。利用校が増えたら、データを 1 つのファイルからデータベース（PostgreSQL など）に移す
- **実機での通知確認**：iPhone・Android・学校のパソコンで、実際に通知が届くことを確認する
- **初期データの登録**：協議会・各市町村の管理者アカウントを発行し、各市町村が学校・学童のアカウントを発行する（デモ用データは削除）
- **運営体制**：連絡協議会の構成と幹事市町村、技術的な保守の委託先、問い合わせ窓口、費用負担を決める
- **規約の確定**：利用規約・プライバシーポリシーのたたき台を、関係者・専門家の確認を経て確定する

## ファイル構成

```
server.js          サーバー（API・リアルタイム通知・セキュリティ設定）
lib/store.js       データと業務ルール（下書き・公開・承認・確認など）
lib/webpush.js     スマホ・パソコンへのプッシュ通知（外部ライブラリなし）
lib/totp.js        2段階認証（スマホアプリの6桁コード）
lib/seed.js        デモ用データ
public/            画面（学校・学童・協議会/市町村・保護者）、通知用 sw.js、規約 terms.html
test/              自動テスト
Dockerfile         サーバーに置くための設定
```
